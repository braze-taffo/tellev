# AI 协作创建角色卡与世界书：实施计划

状态：方案记录，尚未开始修改应用代码。本文记录已经明确的需求、实施顺序和验收条件；具体交互与技术细节可在实施中调整，但不得降低双端运行要求。

## 一、已经确定的要求

1. 用户从零开始，通过与 AI agent 对话创建角色卡或世界书。agent 应参与构思、写作、整理、预览和修订，而非只把问答填入固定表单。
2. 从第一版起，生成的**同一份角色卡及其前端**必须能在 SillyTavern 和 Tellev 实际运行。导出成功、静态预览成功或字段可解析，都不能替代双端运行验收。
3. 支持 AI 生成卡片前端，包括展示和交互，并在应用内渲染、预览与调试。
4. 支持独立世界书与角色卡内嵌世界书；支持从用户提供的长篇原文提炼世界书，保留来源依据供用户校对。
5. 当前阶段只写计划，不修改应用代码。酒馆助手与提示词模板未完全兼容可能导致的失败频率，待功能实现后用实际样本测试和统计，再讨论结论。

## 二、研究与现有基础

- 参考 TavernWeave 的创作维度与产物拆分：角色本体、开场、示例、世界书、状态与变量、前端、运行依赖、源文件与导出物。参考其方法，不直接移植仓库代码或模板；若日后复用内容，先确认许可证与署名条件。
- 以 Character Card V2/V3 规范及 SillyTavern 文档作为交换格式与行为基线，结合 Tellev 当前导入、导出、提示词组装和 WebView 运行能力，建立可执行的兼容矩阵。
- Tellev 已有角色卡和世界书模型、创建/编辑流程、JSON/PNG/WebP/CHARX/BYAF 导入能力、卡片导出能力，以及聊天中的前端 WebView/脚本宿主。这些只是起点，需逐项验证字段往返、脚本权限、变量与提示词行为。
- Tellev 当前仅支持部分酒馆助手式脚本；对部分 iframe 和第三方扩展的支持有限。已有特定卡片的局部测试不能推断所有生成卡片都兼容。

## 三、产品流程

1. 用户选择“创建角色卡”或“创建世界书”，可输入一句想法、完整设定或长篇原文，也可先从空白对话开始。
2. agent 判断已有信息和影响最大的缺口，按需提问，给出可直接修改的写作草案；用户可随时用自然语言改变方向。
3. 草案被保存为独立的创作会话与结构化产物。每次修改显示所影响的字段、世界书条目和前端资源；支持回退、局部重写和手工编辑。
4. 预览同时展示卡片文本、实际提示词/世界书触发结果、前端效果与兼容诊断。用户能看到哪些内容会进入模型上下文。
5. 导出前执行规范检查和双端运行验收。双端兼容的内容才能标记为“可在 SillyTavern 与 Tellev 运行”。未通过时说明具体阻碍并继续修复。

## 四、创作维度与结构

agent 应能处理以下维度，但不能把它们全部变成必答问卷：

| 维度 | 需要考虑的内容 |
| --- | --- |
| 作品形态 | 单角色、叙事者、群像、模拟器、互动故事；用户与角色的关系及扮演边界 |
| 角色内核 | 目标、需求、矛盾、动机、秘密、知识边界、行为准则、关系网络、成长空间 |
| 叙事视角 | 第一/第二/第三人称；第三人称限知或全知；视角人物、镜头距离、哪些信息可被叙述 |
| 文风节奏 | 时态、语气、对话与动作比例、描写密度、叙事速度、语言禁忌与示例 |
| 交互设计 | 用户自主性、角色主动性、冲突与选择、状态变化、失败与恢复、长线一致性 |
| 开场设计 | 首条消息、不同情境的候选开场、入场信息量与可接话的行动点 |
| 世界设定 | 地理、组织、制度、规则、时间线、人物关系、术语；正史、传闻与未定设定的区分 |
| 运行约束 | 提示词注入位置、世界书触发条件、脚本与变量、前端依赖、双端可用性 |

结构化卡片至少覆盖现有核心字段：名称、描述、性格、场景、首条消息、备选开场、示例对话、系统提示、历史后提示、作者说明、标签及内嵌世界书。应保留规范扩展字段与未知字段，避免编辑后丢失。写作内容须与机器可用的配置分开保存，以便重生成和对比。

## 五、长文本提炼世界书

1. 接收粘贴文本及后续可用的文件导入。保存原文或可恢复的来源引用、摘要和校验值；明确告知大小与处理进度，不静默截断。
2. 按章节/场景等语义边界分段，控制模型上下文预算，并以适当重叠处理跨段关系。处理过程可检查、可中断、可恢复。
3. 先抽取人物、地点、组织、事件、规则、物品、术语、时间线和关系，再合并同名异写与跨段重复；把冲突、传闻、推断和原文事实分开。
4. 每条候选条目保存来源片段/位置、证据、置信或待确认状态；不能依据模型猜测悄悄补全原文没有的事实。用户可批量审阅、修改、合并或删除。
5. 生成可独立注入上下文的条目正文、主关键词和别名、次级条件、常驻/条件触发、排序和预算建议。特别检查中文无空格文本的关键词命中与误触发。
6. 用正例和反例测试触发，检查上下文体积、条目冲突和剧透风险。用户可选择保存为独立世界书或嵌入角色卡。完整来源资料与精简运行条目分别管理。

## 六、前端生成与渲染

支持从简单到复杂的四类产物：消息内 HTML/CSS 展示、交互状态面板、开场页面、与对话同层的完整界面。每类都要定义其在 SillyTavern 和 Tellev 的共同运行契约。

- 保存可编辑的 HTML/CSS/JS 源文件、所需脚本/正则/变量与资源清单，记录依赖、入口及版本；导出后仍能复现运行效果。
- 应用内提供手机尺寸预览、交互测试、脚本错误和依赖诊断。预览应调用尽量接近正式聊天的渲染与状态接口；最终仍以真实聊天运行结果为准。
- 对移动端尺寸、深浅色主题、滚动、点击、输入、状态更新、重新生成和会话恢复进行验证。
- 限制脚本权限与外部资源，明确隔离模型生成的代码；可用能力以双端实际支持的接口为准。
- 若所需交互超出 Tellev 当前兼容范围，应实现缺失的运行能力或将前端调整为效果等价的可移植实现，并再次在两端验证。不能用截图相似代替功能一致。

## 七、实施顺序与交付检查点

### 阶段 0：兼容基线

- 固定测试用的 SillyTavern 版本与 Tellev 官方/MNN 版本，列出卡片格式、提示词模板、酒馆助手接口、变量、正则、世界书和前端能力的支持矩阵。
- 选取最小卡片、含世界书卡片、带交互前端卡片作基准样本，记录双端真实运行差异。

### 阶段 1：创作会话与结构化草案

- 建立不依赖已选角色/聊天会话的创作对话、草案持久化、版本回退和增量修订。
- 把创作维度转化为 agent 指导规则与可编辑字段；对不足的信息有选择地提问，并生成完整文案及多个开场。

### 阶段 2：世界书提炼

- 完成长文本分段、抽取、来源追踪、去重、冲突审阅与条目生成。
- 接通独立世界书和卡内世界书的保存、编辑、触发预览及导出。

### 阶段 3：前端创作与运行

- 生成前端源文件与依赖清单，接入应用内预览和诊断。
- 补齐通过双端基准测试所需的 Tellev 运行能力，逐级验证四类前端。

### 阶段 4：导出、回导与端到端验收

- 验证目标格式的字段与扩展字段往返；检查 JSON/PNG/CHARX 等实际支持路径，不预设所有格式功能相同。
- 使用同一导出物分别在 SillyTavern 和 Tellev Android 上创建聊天，检查开场、对话、提示词注入、世界书触发、前端显示和交互、状态持续与恢复。
- 对共享实现，在官方与 MNN 两个工作树分别构建、测试和运行核查；区分技术验证、用户功能验收与发布授权。

### 阶段 5：实现后的兼容性评估

- 准备覆盖角色类型、叙事视角、四类前端、酒馆助手/提示词模板依赖、独立/内嵌世界书和长文本来源的代表样本。
- 记录每份卡片的双端结果、失败位置、可复现步骤和修复成本，统计失败比例及成因。此时再与用户讨论兼容问题发生频率及后续优先级；目前不作“大概率/小概率”判断。

## 八、验收门槛

- 创作会话能从空白想法产生可编辑、可回退的完整角色卡或世界书，用户可控制叙事视角与写作风格。
- 长文本处理无静默截断；重要条目有原文依据，事实、传闻和推断可区分；触发正反例通过。
- 卡片、世界书、前端与资源导出后可回导，核心字段和扩展数据不丢失。
- **同一份生成产物在 SillyTavern 和 Tellev 的真实聊天中均能运行；前端主要交互在两端可用。此项为第一版发布门槛。**
- 不通过时给出可复现的阻碍，不能标记为双端兼容。用户对内容质量的接受与技术运行验收分别记录。
